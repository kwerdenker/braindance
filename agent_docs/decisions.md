2026-07-31 — Q: Trust `vendor-check` alone that the rebuild happened? → Decision: no, probe the artifact. `nm -gU | grep -ci thread`, imported pthread symbols and `std::thread` machinery all read the same on a stale library and a threaded one, because libfreenect2 already threads its packet processors. The discriminating probe is the string `LIBFREENECT2_REG_THREADS`, absent from the Jul-30 prefix and present after the rebuild.
2026-07-31 — Q: Is `registration-check`'s default run enough? → Decision: no, run `--persistent-subject` too. The default compares `apply()`'s four-argument form both sides, but `grabber.cpp` ships the seven-argument one, so the documented invocation proves a call shape the product does not use. Both arms are bit-identical on the 72-frame corpus.
2026-07-31 — Q: Preserve the stale `vendor/prefix` before rebuilding? → Decision: yes. It is exactly the "prefix built from different source" that `vendor-check`'s recorded gap needs as a falsification control, and the rebuild would have destroyed it. Kept as `prefix-stale-jul30` in the session scratchpad.
2026-07-31 — Q: Which mutation convention should `guard-check` follow? → Decision: the four server tools', not the two vendoring ones'. Caught exits non-zero, the refusal message reads `unknown mutation X - have a, b`, and `FAIL` carries two leading spaces, so `sweep-all.mjs` can enumerate and count it. The two vendoring tools are not sweepable on any of those three points and that is a known divergence, not a thing to spread.
2026-07-31 — Q: Does the WebSocket origin check make `--host` unnecessary? → Decision: no, they are different failures. Host equality cannot survive DNS rebinding — a name the attacker controls resolving to the node's LAN address makes `Origin` and `Host` genuinely equal — so the guard stops the drive-by and the loopback default stops the thing that has to be routable to be attacked at all.
